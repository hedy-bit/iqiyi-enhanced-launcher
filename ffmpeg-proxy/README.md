# FFmpeg 兼容代理（本机诊断）

当前产物是解码接口观察代理，不是重新实现的 FFmpeg，也不是已经完成的 PotPlayer 外播桥。

## 工作方式

- 对指定 SHA-256 的爱奇艺 avcodec-61.dll 保留全部 165 个导出名称和原序号。
- 158 个接口通过 PE 转发机制交给原版副本 `iqiyi_codec_original.dll`；7 个接口包装后调用同一副本。
- 包装函数只记录编码器名称、媒体类型、成功送包/收帧次数，不修改传入对象、解码参数或返回值。对象保持不透明，不依赖私有结构偏移。
- 增加 `iqiyi_proxy_snapshot(buffer, capacity)` 导出，查询内存中的 JSON 计数。没有后台线程、网络服务或日志写盘。
- 原版 DLL 副本和私有依赖仅暂存于 `stage`。未覆盖安装目录，未加入启动脚本。

## 构建和测试

运行 `Build-Test.ps1`：校验原库哈希、准备依赖、使用 MSVC x64 编译，然后在独立 Python 进程中测试。

测试覆盖：165 个名称与序号的解析、版本转发、合成 PNG 和自建 AV1 10-bit 视频首帧解码、无可用帧及流结束的返回值、40 次并发解码及释放后上下文计数。结果在 `test-report.json`。测试验证了返回码和成功收帧，没有比较解码像素内容；这不等价于客户端兼容性或 DRM 正片外播测试通过。

`probe-live-codecs.py` 可对正在运行的 QyPlayer 做 25 秒同接口观察，结束自动脱离。它只读取编码器标识和计数，不加载此代理或替换客户端 DLL。

实际观察已捕捉到客户端按名称打开 `av1` 解码器，并成功返回 110 帧，见 `live-codec-report.json`。这是原客户端调用的观察结果，说明目标接口确实处理 AV1 视频；并不表示客户端已经加载本代理。

## 接入限制

不要把此文件单独复制进安装目录：它依赖原版副本，且客户端可能校验安装文件。当前也没有媒体外送功能。只有先证明该接口处可获得目标视频、完成客户端独立副本中的验证和恢复测试后，才有理由考虑部署。

仓库仅发布本项目编写的实验源码。构建产物和 `stage` 原安装文件副本留在本机，不应当作自行编写的源码发布；不包含完整影音转接实现。

接口依据：[FFmpeg 7.0 文档](https://ffmpeg.org/doxygen/7.0/group__lavc__core.html)、[Microsoft 导出转发文档](https://learn.microsoft.com/en-us/cpp/build/reference/exports?view=msvc-170)。
